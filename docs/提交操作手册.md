### ⚠️ 为什么必须走 fork（实测结论，别踩第二次）

**不能**把功能分支直接推到专属仓。实测推 `feat/board-port` 到
`open-vela/contest2026_076_VelaMotion` 会被仓库 ruleset 拒绝：

```
remote: error: GH013: Repository rule violations found for refs/heads/feat/board-port.
remote: - Required status check "cla/signature" is expected.
remote: error: push declined due to repository rule violations
```

关键点：**这不是权限问题**（没权限会报 `denied`）。该 ruleset 要求
`cla/signature` 状态检查通过才能推送，**推新分支也算**；而这个状态只有在
PR 上才会由 CLA 机器人产生 —— 于是形成死锁。**绕开办法就是 fork**：
fork 出来的是你自己账号下的独立仓库，上游的 ruleset 不作用于它。
这也正是官方指南把流程写成「fork → 开发 → PR」的原因。

## 3. 签名 CLA 并 Fork（必须先做，且是本人操作）

**3.1 签 CLA**（法律行为，必须你用 `yangcong-bit` 账号本人签署）

打开 https://openvela.com/#/community/cla ，用报名时的 GitHub 账号签署。
不签的话 PR 上的 `cla/signature` 检查不会通过，无法合入。

**3.2 Fork 专属仓**

打开 https://github.com/open-vela/contest2026_076_VelaMotion/fork ，点 **Create fork**，
得到 `https://github.com/yangcong-bit/contest2026_076_VelaMotion`。

**3.3 把 fork 加为远程并推送功能分支**

```bash
cd C:\Users\ZYS20\Desktop\openvlea\openvela\contest2026_076_VelaMotion

git remote add fork https://github.com/yangcong-bit/contest2026_076_VelaMotion.git
git push -u fork feat/board-port
```

推送目标是 **fork**，不是 `origin`。`origin` 保留指向上游，方便后续同步。

## 4. 发起 PR 并自行合入

从 fork 的分支向上游 `dev-ai-contest-2026` 开 PR：

https://github.com/open-vela/contest2026_076_VelaMotion/compare/dev-ai-contest-2026...yangcong-bit:contest2026_076_VelaMotion:feat/board-port?expand=1

1. Base 选 `dev-ai-contest-2026`，head 选 fork 的 `feat/board-port`，创建 PR。
2. **PR 上会跑 `cla/signature` 检查**：
   - 若已按 3.1 签好 CLA，通常自动通过；
   - 若未通过，**不需要重建 PR**，在原 PR 下评论 `/check-cla` 触发复检；
   - 仍未通过就说明 CLA 没签成功或签错了账号，回 3.1 检查。
3. 检查通过后点 **Merge pull request** 自行合入（无需等组委会）。

> 合入后分支可以删除，fork 也可以留作后续提交使用（大赛提交期内可能还要再提）。

## 5. 归集 AI Coding 日志（**必须做，且要手动 push**）

采集器只在「识别到 `.repo/` 的 openvela 工作区」内激活，
且**只写本机文件、永不自动 push**。请到**实际做开发的那台机器**上执行：

```bash
# 前提：已用 repo init + repo sync 拉过工程
cd <工作区根>/contest2026_076_VelaMotion

# 1) 一次性安装
bash ../.claude/skills/contest-log-collector/onboarding/install.sh \
  --team-id contest2026_076_VelaMotion \
  --github-login <你的 GitHub 用户名>

# 2) 健康检查
bash ../.claude/skills/contest-log-collector/onboarding/verify-setup.sh

# 3) 补回安装 hook 之前的历史会话（可重复执行，不会重复导出）
contest-snapshot --backfill

# 4) 预览 → 确认导出（不加 --confirm 只预览，不写文件）
contest-snapshot --list
contest-snapshot --latest --confirm

# 5) 校验 + 提交
python3 ../.claude/skills/contest-log-collector/tools/validate-log.py logs/
git add logs/ && git commit -s -m "logs: capture AI coding sessions" && git push
```

**要点**

- 只有 4 种工具会被采集：**Claude Code**（含 AIoT-IDE）、**AIoT-IDE**、
  **OpenCode**、**Codex**。用 ChatGPT / Cursor / 直接调 API 的对话
  **采集不到、不计工时**。
- 每名队员一个 `logs/<自己的 github_login>/` 目录；多人协作时各自
  `git pull` 后再 commit，不会冲突。
- 不要手工编辑 `.jsonl`（`validate-log.py` 会检测篡改）；要撤回就删文件。
- Windows 用户在 **Git Bash** 中执行，需要 Python 3 + Git，不需要 WSL。

> 这一步同时决定了 MiMo Token 追加申请能否通过 —— 组委会第一步就是查 `logs/`。
