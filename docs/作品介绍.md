## 一、作品概述

**SomatoSync** 是一套面向**医疗级全身运动障碍量化追踪**的多节点体感数据同步系统：
在人体上布置 12 个可穿戴 IMU 节点，通过自研的 **ESP-NOW TDMA 时分多址调度＋
自适应跳频（AFH）** 协议，把多路高频姿态数据无碰撞、低延迟地汇聚到网关；
网关经以太网上送 ROS 2 上位机，完成骨架重建、运动功能评估与 AI 康复报告生成。

该系统原本基于 ESP-IDF 开发并已在真机跑通。本次参赛的核心工作是
**把该系统的两块自研板卡适配到 openvela**：完成板级 bring-up、外设引脚与供电时序、
defconfig 配置与构建系统集成，使 openvela 能在两块板上正常启动、
串口控制台可用、基础外设可逐项验证，并把 SSD1306 显示子系统落地为
openvela 标准图形设备（满足大赛「至少落地图形 / AI / 多媒体之一」的要求）。

## 二、背景与痛点

**临床痛点**：脑卒中、帕金森、脑瘫、多发性硬化、骨关节术后、运动损伤等
运动功能障碍的评估，长期依赖治疗师的主观观察与量表打分，存在
**量化程度低、复诊间隔长、居家康复缺乏客观依据**的问题。光学动捕精度高但
价格昂贵、必须在实验室内使用，无法覆盖居家场景。

**技术痛点**：可穿戴方案要解决的核心矛盾是
**多节点 × 高频采样 × 无线无碰撞**。ISM 频段拥挤，通用 CSMA 类 MAC 在高节点数、
高上报率下丢包与延迟急剧恶化；而医疗评估要求时序严格对齐，丢包会直接破坏
关节角度的连续性。

**我们的解法**：用 TDMA 给每个节点分配固定时隙，从机制上消除碰撞；再用
自适应跳频规避窄带干扰；节点侧在片内完成姿态融合，只上报解算结果，
把无线带宽压力降到最低。

## 三、总体方案与系统架构

五层技术栈：

| 层 | 职责 |
| --- | --- |
| 感知层 | 节点端双路 ICM-42688 高频 IMU 采集 |
| 解算层 | 片内双 ESKF 姿态融合、双 IMU 在线校准 |
| 传输层 | ESP-NOW TDMA 时隙调度 ＋ 自适应跳频 ＋ 背压流控 |
| 汇聚层 | 网关端以太网（W5500）转发、SD 卡原始数据落盘、OLED 状态显示 |
| 应用层 | ROS 2 上位机：UDP 桥接 → 正运动学 TF2 骨架 → 康复指标 → AI 报告 |

**双核隔离**：Core 1 负责高频计算（采集与解算），Core 0 负责射频与网络；
两核之间只用无锁原子原语通信，禁止互斥锁，避免高频路径被调度抖动打断。

**信标驱动**：节点永远被动响应网关的 TDMA Beacon，不主动发起，
从设计上消除上行竞争。

## 四、硬件设计

两块自研板均为 ESP32-S3 方案，形态与职责不同。

**网关板（同步中心 / Master）**

- 以太网：WIZnet W5500（SPI2）—— 承载向 ROS 2 上位机的数据上送
- NFC：NXP PN5180（SPI3）—— 「碰一碰」快速配网
- 显示：SSD1306 128×64 OLED（I2C0）—— TDMA 调度状态、节点在线数、存储状态
- 存储：microSD，1-bit SDMMC —— 原始动捕数据落盘
- 射频：Wi-Fi / ESP-NOW —— TDMA Beacon 广播与节点数据汇聚

**可穿戴节点板（采集终端 / Slave）**

- 传感：双路 ICM-42688，挂在**两条独立 SPI 总线**上（SPI2 / SPI3），
  各带独立 LDO 使能，并注入外部 32.768 kHz 时钟以稳定采样时基
- 显示：SSD1306 128×64 OLED（I2C0，带电源门控，可在帧间完全断电）
- 触觉：DRV2605（I2C0）—— 用于配网与状态反馈
- 电源：电池分压 + 接地 MOS 门控（ADC1_CH1），避免分压电阻长期漏电
- 射频：Wi-Fi / ESP-NOW —— 在分配时隙内无碰撞上报

**引脚映射**逐条转写自原 ESP-IDF 固件，并在提交文档中标注了
必须对照原理图（`docs/reference/SCH_主机_2026-05-22.pdf`）复核的要求。

## 五、本次参赛的核心工作：openvela 板级适配

### 5.1 适配定位

openvela 已支持 ESP32-S3 **芯片层**（Xtensa 双核、Wi-Fi、BLE、SPI/I2C/SDMMC、
USB-Serial）；但本队的两块板卡是**尚未适配过的自有硬件**。因此工作量落在
板级：引脚与供电时序、外设组合、板级 bring-up、defconfig 与构建系统集成。

### 5.2 工程约定对齐

适配以 `vendor_espressif/boards/esp32s3/esp32s3-eye`（openvela 官方已适配的
ESP32-S3 参考板）为唯一可信基线，逐文件核对其工程约定，
而不是套用大赛模板里那个通用占位骨架。

**一个关键的工程判断**：大赛模板把板级目录映射到 `vendor/openvela/boards/`，
但 ESP32-S3 的板级配置实际是通过 `CONFIG_ARCH_BOARD_CUSTOM_DIR` 机制定位的，
板目录**必须与芯片支持放在一起**（`vendor/espressif/boards/esp32s3/`），
否则 Kconfig 与板级源码都加载不到。本作品据此修正了 manifest 映射位置。

### 5.3 交付内容

```
board/somatosync_esp32s3/
├── Kconfig                       # 板型二选一（网关 / 节点）＋ 各外设开关
├── CMakeLists.txt                # 板级 CMake 入口
├── include/
│   ├── board.h                   # 两块板的完整引脚映射（条件编译区分板型）
│   └── somatosync_esp32s3.h
├── src/
│   ├── somatosync_boot.c         # esp32s3_board_initialize / board_late_initialize
│   ├── somatosync_appinit.c      # board_app_initialize（BOARDIOC_INIT）
│   ├── somatosync_bringup.c      # 板级外设总 bring-up（单外设失败不阻断整板）
│   ├── somatosync_board_lcd.c    # SSD1306 OLED（图形能力落地点）
│   └── somatosync_board_eth.c    # W5500 以太网板级 glue
├── configs/
│   ├── gateway/defconfig         # 网关板配置
│   └── node/defconfig            # 节点板配置
└── README_zh-cn.md               # 板级适配指南（编译 / 烧录 / 逐外设验证）
```

### 5.4 图形能力落地（合规要点）

大赛要求项目须使用 openvela 提供的系统能力，且至少落地**图形 / AI / 多媒体**
之一。本适配落地**图形**：

1. SSD1306 面板经 `board_lcd_initialize()` + `lcddev_register(0)` 注册为
   标准 NuttX LCD 设备，暴露 `/dev/lcd0`；
2. 使能 `CONFIG_LCD_FRAMEBUFFER` 后进一步成为标准 framebuffer，
   **LVGL 与 fb 类 demo 无需改动即可运行**；
3. 面板内容对应真实系统功能：网关显示 TDMA 调度状态、节点在线数、
   存储状态；节点显示电量与姿态解算状态 —— 即原固件 OLED 菜单的 openvela 版本。

### 5.5 复用而非重造

W5500 以太网协议驱动在 openvela 的 NuttX 主线中已存在
（`drivers/net/w5500.c`）。本适配没有重写驱动，只按
`struct w5500_lower_s` 契约提供板级 glue（SPI 总线、RSTn、INTn）。
这既减少了代码量，也保证了后续可以向 openvela 上游提交。

---

### 5.6 当前交付边界（诚实说明）

本次参赛交付的是 **openvela 板级适配**，**不是**把 SomatoSync 应用搬到 openvela 上运行。

**已交付**

- openvela 能在两块自研 ESP32-S3 板上启动运行（`open-vela/nuttx`，分支 `dev-ai-contest-2026`）
- 引脚映射、板型划分（gateway / node）、板级驱动初始化：
  SSD1306 OLED（`/dev/lcd0`）、W5500 以太网、microSD、Wi-Fi / ESP-NOW 底层能力
- 两套 defconfig 均编译通过并产出可烧录镜像（网关板 834.9 KB、节点板 671.9 KB）
- 板级函数经符号表核对确认位于镜像内（`somatosync_bringup`、`somatosync_w5500_initialize`、
  `board_lcd_initialize`、`esp32s3_spi2_status`）

**未交付**

ESP-NOW TDMA 时隙调度、双 ESKF 姿态融合、网关状态机与 OLED 菜单、AI 康复报告与
ROS 2 上位机链路。它们建立在 ESP-IDF 的 `esp_now_*` API 与 FreeRTOS 双核任务模型之上，
必须按 NuttX 的 POSIX 模型重新设计，属于第二阶段工作。

| 原方案（ESP-IDF） | 目标（NuttX / POSIX） |
| --- | --- |
| `esp_now_send` / `esp_now_recv` | raw socket + `esp32s3_wifi_adapter` |
| FreeRTOS task / queue | NuttX task / `mq_*` / pthread |
| Core0 / Core1 双核无锁 IPC | NuttX SMP spinlock / atomic / CPU 亲和 |
| `esp_timer_get_time()` | `clock_gettime()` |
| `nvs_flash` | MTD + littlefs / FAT |

**烧录后可验证的水平**：`nsh>` 命令行 + 设备节点，即 `uname -a`、`ls /dev`、
`i2c dev 0x03 0x3c`、`ifconfig eth0` —— 操作系统启动、外设可控。
这是板级适配赛道的验收范围。

## 六、关键技术与创新点

1. **TDMA ＋ AFH 的无碰撞上行**：给每个节点分配固定时隙，从机制上消除碰撞；
   自适应跳频规避窄带干扰；配合背压流控与无延迟丢弃策略，保证时序连续性。
2. **双 ESKF ＋ 双 IMU 在线校准**：单节点两路 IMU 融合，抑制漂移并提升
   姿态估计鲁棒性，解算全部在片内完成，只上报结果以节省带宽。
3. **双核隔离 + 无锁 IPC**：计算与射频分核，跨核仅用原子原语，
   避免高频路径被调度抖动影响。
4. **产品化的板级工程**：NFC 碰一碰配网、FOTA 无线升级、
   电池门控与低功耗设计、OLED 菜单与五向键交互 —— 不是实验室原型。
5. **AI 贯穿全链路**：网关侧对时序数据做 AI 康复分析并生成报告；
   开发侧全程使用 AI Coding 并有 Skill 沉淀。

## 七、运行方式与验证

```bash
# 拉取工程
repo init -u https://github.com/open-vela/contest2026_076_VelaMotion \
  -b dev-ai-contest-2026 -m contest2026_076_VelaMotion.xml
repo sync -c -j8

# 编译（网关板 / 节点板）
cd <openvela 工作区根目录>
./build.sh vendor/espressif/boards/esp32s3/somatosync_esp32s3/configs/gateway -j$(nproc)
./build.sh vendor/espressif/boards/esp32s3/somatosync_esp32s3/configs/node    -j$(nproc)

# 烧录（simple-boot，单镜像到 0x0）
esptool --chip esp32s3 --port "$PORT" --baud 460800 \
        --before default-reset --after hard-reset write-flash 0x0 nuttx/nuttx.bin
```

启动后在 `nsh>` 逐项验证：

```
nsh> uname -a                       # xtensa somatosync_esp32s3
nsh> ls /dev
nsh> i2c dev 0x03 0x3c              # SSD1306 ACK
nsh> ifconfig eth0                  # 网关板：W5500
nsh> mount -t vfat /dev/mmcsd1 /mnt # 网关板：microSD
```

完整的逐外设验证清单见仓内 `board/somatosync_esp32s3/README_zh-cn.md`。

## 八、AI Coding 开发流程与 Skill 沉淀

本次开发全程使用 AI Coding，完整对话日志见仓内 `logs/`。

| 环节 | AI 承担的工作 |
| --- | --- |
| 规范调研 | 通读大赛官方文档与赛道指引，比对 `esp32s3-eye` 与大赛模板骨架，识别出 `ARCH_BOARD_CUSTOM_DIR` 才是正确的板级加载路径 |

**Skill 沉淀**：`openvela-board-porting`

openvela 适配」的全流程固化为可被 AI 助手自动发现的技能，覆盖：选定同芯片

## 九、项目完整度与商业潜力

**完整度**：系统本体（固件 + 上位机 + 文档 + 演示）已跑通；
本次在此基础上补齐 openvela 板级适配，含可编译的板级代码、两套 defconfig、
板级适配指南、作品说明与提交手册。

**商业潜力**：

- **场景真实**：康复科与居家康复是可明确付费的场景，且当前缺乏可量化的
  低成本方案；光学动捕的价格与场地限制正是本方案的空间。
- **形态成熟**：12 节点可穿戴 + 网关 + 上位机报告，已是可交付的产品形态，
  而非概念验证。
- **可规模化**：核心是通用 MCU + 通用 IMU + 自研协议，BOM 可控、易于量产；
  适配 openvela 后具备了接入更广泛 AIoT 生态与更多芯片平台的能力，
  有助于进一步降本与扩展产品线（如扩展到手环、手表形态）。
