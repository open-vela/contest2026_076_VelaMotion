# SomatoSync 硬件排雷与故障分析报告

本文档详述了 SomatoSync 系统在硬件开发、传感器调试及充电联调阶段发现的重大物理设计漏洞、寄存器移位缺陷与电池跳变现象，并给出了工程上的修复方案及 V3.0 的物理改板规划。

---

## 1. SSD1315 OLED 屏幕漏电与假死锁死排查 (V2 版本)

### 1.1 故障现象
在 V2.0 电路调试中，系统拔掉 USB 并通过滑动开关断电后，整机并未关机，而是卡在 `2.0V ~ 2.5V` 的悬空电压上，OLED 屏幕微亮并显示残影。此时系统处于“半死”状态，无法通过滑动开关正常再次启动。

### 1.2 原因剖析
- **时序漏洞**：系统采用单 `3.3V` DCDC 电轨设计，利用 ESP32-S3 的 GPIO35 直接控制 OLED 供电轨（`VBAT_OLED`）的 PMOS 负载开关。
- **电能反向倒灌**：关机时，`3.3V` 主电轨跌落，单片机 GPIO35 的推挽状态进入高阻悬空状态，导致控制 PMOS 的栅极电平发生漂移。SSD1315 驱动 IC 规格书严格要求“*VDD 绝不能比 VBAT 先掉电*”。由于主控先失能，导致 OLED 内部 `VBAT` 通过寄生二极管向主 `VDD` 倒灌漏电，将电轨锁死在 2.0V 附近，导致主 CPU 锁相环假死。

### 1.3 修复方案与物理整改 (V2 阶段)
- **硬件整改**：
  1. 切断主板上 Q2 (AO3400A) NMOS 栅极与单片机 GPIO35 之间的铜线。
  2. 将 Q2 的栅极直接连接到滑动开关/物理开关控制 DCDC 的 **`DC_EN`（使能脚）**上，实现断电物理切断。
  3. 单片机侧的 GPIO35 引脚设为空脚悬空（NC）。
- **物理成效**：当物理开关拨至 OFF 时，`DC_EN` 瞬间拉低，PMOS/NMOS 门控管瞬间强截止，彻底截断电池 `VBAT_OUT` 链路，整机漏电降为 **`0µA`**。

## 2. ICM-42688-P 中断超时与 ODR 频率降级排雷

### 2.1 故障现象
在启用硬件数据就绪（DRDY）中断驱动的 ESKF 姿态解算任务时，系统启动后立刻抛出：
```text
W (2542) main: 中断超时 101 次, 切换到轮询模式 (GPIO10 INT1 未连接?)
```
且在轮询模式日志中显示 `INT_CNT`（硬件中断计数）匀速上涨，证明中断引脚确实被触发了，但负责接收信号的 `imu_task` 却始终超时。

### 2.2 深度排查与 Root Cause
1. **FreeRTOS 任务通知参数错用**：
   在 `icm42688_wait_drdy` 函数中，对 `xTaskNotifyWaitIndexed` 的调用为：
   ```c
   // 错误代码：ulBitsToClearOnEntry 被错误填入了通知位
   xTaskNotifyWaitIndexed(0, dev->notify_bit, dev->notify_bit, &bits, ticks)
   ```
   这导致如果 ISR 在任务进入等待状态之前触发，任务一进入等待函数就会**先把通知位清空**，然后死等。因为 IMU 中断被配置为 **Latched（锁存）** 模式，如果不去读取 SPI 数据清空内部寄存器，引脚会一直保持高电平，无法产生下一个上升沿，导致任务死锁超时。
2. **寄存器写入位移缺陷 (ODR 从 1000Hz 坠落至 100Hz)**：
   应用层设定了 1000Hz ODR 并将超时门限设为 2ms，但驱动代码中写入 `ACCEL_CONFIG0` 寄存器时：
   ```c
   // 原始错误代码：将 ODR 移位左移了 3 位
   uint8_t accel_cfg = (dev->cfg.accel_fs & 0x1C) | (dev->cfg.accel_odr << 3);
   ```
   - 对照官方数据手册，`ACCEL_CONFIG0` 的 `[3:0]` 位对应 `ACCEL_ODR`。
   - 头文件中 `ICM42688_ODR_1000HZ` 为 `0x0B`。
   - 执行 `0x0B << 3` 变成了 `0x58` 写入寄存器，导致低 4 位实际被写入了 `1000` (即 `0x08`)。**0x08 在手册中恰巧对应的是 100Hz ODR**。同时，高位量程也被强制篡改为了 4g（原本设定 16g）。IMU 10ms 抛一次中断，主程序 2ms 超时，导致永远报错超时。

### 2.3 修复方案
1. **重构寄存器枚举**：
   在 `icm42688_reg.h` 中，对照手册修正 ODR 与 FS（量程）的十六进制定义，使量程在头文件中即完成左移 5 位。
   ```c
   typedef enum {
       ICM42688_ACCEL_16G = (0x00 << 5),
   } icm42688_accel_fs_t;
   ```
2. **修正写入逻辑**：
   ```c
   uint8_t accel_cfg = dev->cfg.accel_fs | dev->cfg.accel_odr;
   ```
3. **修复任务通知**：
   将 `ulBitsToClearOnEntry` 设为 `0`，仅在退出时清除通知状态，确保不丢失任何在途的中断信号。

## 3. BQ24040 快速充电插线瞬间电压跳变分析

### 3.1 故障现象
在将节点插入 USB 充电线时，ADC 采样得到的电池电压会瞬间从真实的 `3.2V` 跳变上升至 `4.0V`。

### 3.2 物理成效剖析 (IR Drop)
该现象是由**充电端内阻压降叠加 (IR Drop)** 引起的。
- **充电参数**：BQ24040 配备 1kΩ 的 `ISET` 电阻，根据公式 $I_{CHG} = 540 / R_{ISET}$，芯片输出恒定 **`540mA`** 的充电电流。对于 600mAh 电芯，这接近 **`0.9C`** 的急充倍率。
- **压降计算**：此时 ADC 探测的是 BQ24040 的 `OUT` 引脚。
  $$V_{ADC} = V_{Battery\_Open} + I_{CHG} \times R_{\text{total\_impedance}}$$
  由于电芯自身的极化内阻、保护板 (DW01+8205A) MOSFET 导通电阻以及 JST 连接线接触电阻，充电回路的总阻抗约为 `1.5 Ω`。为了把 540mA 的恒定电流压入电池，BQ24040 必须主动抬升其 `OUT` 端电压至 4.0V，导致测得的电压瞬间暴涨 800mV。

### 3.3 ULP 协处理器化危为机（设计预留）

> [!NOTE]
> 本节描述的 ULP 自适应状态机为设计目标，当前演示模式下 ULP 协处理器**二进制已加载但未启动运行**（详见 [硬件与电源管理架构 §4](../architecture/硬件与电源管理架构.md)）。充电插入检测改由 **EXT1 唤醒源（CHG 引脚低电平）+ 10s 定时轮询** 兜底实现，确保演示稳定性。

此 800mV 瞬态电压跳变如果处理不当，会欺骗主控的低功耗唤醒逻辑。系统设计了 ULP 协处理器自适应状态机，将其转为最灵敏的“插线传感器”：
- **突变探测**：ULP 协处理器检测到相邻两个采样的电压跃变幅度 $\ge 300\text{mV}$ 时，判定系统外部插入了充电线。
- **低功耗充电保护**：ULP 唤醒主控 CPU 进入专用的充电自保模式：**强行关闭 IMU、关断 Wi-Fi 和 ESP-NOW 射频发送**。仅点亮 OLED 屏幕显示当前的实际电压与 Charging 字样，维持极低的工作电流（<30mA），确保充电安全性并防止假死。

## 4. V3.0 版本改板与升级建议

为根治上述物理硬缺陷，V3.0 改板需执行以下变更：

1. **废弃模拟分压，引入 MAX17048G 纯数字电量计**：
   - 彻底删除 V2 中的 100k+100k 分压电阻及 GPIO1/GPIO2 控制 MOS 管。
   - 引入 I2C 接口电量计 MAX17048G，直接连接电池正负极。免除静态分压功耗（消除 21µA 漏电）。
   - 将 MAX17048G 的报警中断引脚 `ALRT` 连至单片机 GPIO26。
2. **充电指示引脚 CHG_N 接入**：
   - 将 BQ24040 的 `CHG_N` 开漏脚连至主控 GPIO21，用于底层软件进行硬件级充电状态监测（充满判定）。
3. **加粗供电走线**：
   - 主板上电池接线使用 24AWG 或更粗导线，减小充电内阻（IR Drop），将回路阻抗控制在 $0.5\Omega$ 以下。
